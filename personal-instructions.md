# Personal Coding Guidelines

- **Commit messages**: infer *why* from context when possible — the motivation or problem behind it — not just what was changed. For non-trivial or hard-to-reverse changes where the reason isn't clear, ask instead of guessing. Otherwise, proceed with your best guess.
- **Tests and scenario names**: encode *what* behavior is expected — use descriptive test names or scenario titles to document the intended behavior, so the test suite itself serves as the specification.
- **Code comments**: focus on *why not* — why the obvious alternatives weren't chosen, if such alternatives exist. Don't just describe what the code does.
